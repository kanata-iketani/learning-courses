- 問題はすべてオリジナル。外部の問題集の問題文・選択肢を写さない

## 教科書(text)— 各チャプター 3000〜6000 字(20〜30 分で読める)
1. **基礎**: 前提ゼロから。「そもそも何を守るのか、何が起きると困るのか」を具体的な事故の例で
2. **AWS での仕組み**: サービス・機能の動きを、ポリシーの JSON・CLI の出力・ログの1行などの実物で。1行ずつ説明
3. **実務での使い方と判断**: 2〜3 案の比較表(仕組み・良い点・悪い点・運用負荷・コスト)。よくある設定ミスと事故、プロならどう決めるか
4. **構成図**: AWS のサービスが複数出る章では、AWS 公式アイコンの構成図(architecture-beta)を1つ以上。書き方は `~/learning/shared/aws-icons/ARCH_DIAGRAM.md` を読む(ラベルは半角英数のみ。日本語の説明は図の直後に)。流れは sequenceDiagram、手順は flowchart
5. **試験ではこう問われる**: SCS-C03 での出題パターンを 2〜4 行(「最も運用負荷が低い」「最小権限」などのキーワードの読み方)
6. `### まとめ`(3〜5 行)
- 用語は章内の初出時だけ括弧で 10〜25 字のかみ砕き。込み入ったものは小さな節を立てて説明。例え話の段落は書かない。です・ます調、1 文は短く
- 教科書の Markdown の表はアプリで表示できる。ただし表のセルの中に `|` や二重バッククォートを入れない

## 問題(各チャプター 6〜8 問)
- **4択**(5〜6 問): SCS 型のシナリオ「要件(最小権限・運用負荷最小・コスト最小・検知までの時間最短など)を満たす最も適切なものはどれか」を多めに。基礎を確かめる問題も混ぜる。誤答はもっともらしく、本文から明確に誤りと言えるもの。正解位置は均等に
  `{ "question": "…", "choices": ["…","…","…","…"], "correct": 0, "explanation": "正解の根拠と、主な誤答が違う理由(2〜4 文)" }`
- **記述式**(各チャプター 1〜2 問。AI 採点): 設計とその理由、ポリシーを読んで何が許可されるかを説明、対応手順、「何も見ずに 1 分で説明する」
  `{ "kind": "essay", "question": "…", "answer": "模範解答(200〜500 字)", "rubric": ["具体的な採点観点", "…", "…"], "choices": ["⭕ 合格", "❌ 不合格"], "correct": 0, "explanation": "…" }`
- 模擬試験(L23・L24)は 4択の本番形式 50 問。全分野から配点に沿って出す。1 問ごとに丁寧な解説と「L◯ で復習」
