# 超初心者の目で教材を点検・補強する手順

## なぜやるか(ユーザーの指示 2026-11-13)
「全教材ちゃんとそれを通してプログラミングや SQL やその他システム的なすべてを、超初心者が理解できる作りになっているか確認して」。
受講者本人は Python を少し書いた程度。プログラミング・SQL・ネットワーク・OS・クラウドの基礎は浅い前提で読む。

## 点検の観点(1レッスンずつ、全チャプター)
1. **説明なしに使われている用語**: 初出なのに説明がない用語(例: ステートフル、冪等、トランザクション、ハンドラ、環境変数、CIDR、TTL)。前のレッスンで説明済みなら「L◯で見た〜」と一言そえる
2. **説明なしのコード・SQL・コマンド・設定**: 1行ずつ「何をしているか」が書いていないもの。記号(`:=`、`&`、`=>`、`?.`、`::`、`$1`、`*` など)の意味、実行するとどうなるか(出力・結果の表)まで
3. **飛んでいる前提**: 「当然知っている」ことを前提にした説明の飛躍。なぜそうなるのかの一段目が抜けていないか
4. **具体例の不足**: 抽象的な説明だけで終わっている所に、小さな具体例(値の入った表、実行例、パケットの中身、リクエストとレスポンスの実物)を足す
5. **問題の前提**: 本文に出てこない知識がないと解けない問題がないか。あれば本文に足すか、問題を直す

## 直し方
- 本文を直接直す。足すときは、その場で短く(用語は括弧で 10〜25 字。込み入ったものは 3〜6 行の小さな節「◯◯とは」)。大きな基礎が丸ごと抜けている場合は、チャプターの頭に「基礎の基礎」の節を足してよい
- 例え話の段落は書かない。です・ます調。正確さを崩さない(かみ砕いても嘘にしない)
- 既存の問題は削らない。必要なら基礎を確かめる4択を 1〜2 問足してよい
- 社外秘の値を書かない。禁止語は `~/learning/CLAUDE.local.md` の「禁止語」を見る
- 仕上げ: その講座で `go run ./tools/coursegen -only {N} -no-gen` が ALL OK。図を足したら `python3 -P ~/learning/shared/aws-icons/check_diagrams.py <講座>/lesson{NN}` も ALL OK

## 報告(日本語・短く)
レッスンごとに: 直した箇所の数、足した説明の主なもの(用語・コード・前提)、足した問題の数、判断に迷った点。
