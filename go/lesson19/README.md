# Lesson 19 変数のスコープ

Python入門編「変数のスコープ」に対応するレッスンです。Go の変数は `{}` 単位のブロックスコープで、`global` / `nonlocal` はありません。`if v, err := ...` の `:=` が作る意図しないシャドーイングが実務の落とし穴です。

## ch01 ブロックスコープ {}

変数が使える範囲を**スコープ**といいます。Go の変数は、宣言した `{}`（ブロック）の中だけで有効です。Python では if や for の中で作った変数を外でも使えましたが、Go では for や if の中で宣言した変数はブロックを出ると消え、外で使うとコンパイルエラーになります。ループの結果を外に残したいときは、**ブロックの外で先に宣言**してから中で代入します。🟡 「宣言した場所で寿命が決まる」という理屈を理解しましょう。

Python ではこう書いた:

```python
if x > 0:
    msg = "plus"
print(msg)  # if の外でも使える
```

Go ではこう書く:

```go
msg := "" // 外で使いたい変数は外で宣言する
if x > 0 {
	msg = "plus"
}
fmt.Println(msg)
```

### サンプルを1行ずつ読む

- `msg := ""` … if より**前**（外側）で宣言します。中身は空文字列
- `if x > 0 { msg = "plus" ... }` … `=` は代入なので、外側の `msg` に `"plus"` が入ります
- `inner := "if の中だけの変数"` … if の `{}` の中で宣言したので、`}` を出ると使えません
- `// fmt.Println(inner)` … `//` でコメントにしてある行です。コメントを外すと `undefined: inner`（inner が定義されていない）というコンパイルエラーになります
- `for i := range 3 { total += i }` … `i` も for の中だけの変数です。`total` は外で宣言したので、ループ後も 0+1+2 = 3 が残ります

| 変数 | 宣言した場所 | 使える範囲 |
|---|---|---|
| `x`, `msg`, `total` | main の `{}` 直下 | main の最後まで |
| `inner` | if の `{}` の中 | その if の `}` まで |
| `i` | for の頭 | その for の `}` まで |

### 実行結果

```text
if の中だけの変数
plus
3
```

## ch02 シャドーイング

内側のブロックで外側と**同じ名前**の変数を `:=` で宣言すると、内側ではその新しい変数が外側の変数を隠します。これを**シャドーイング**といいます。外側の変数が消えるわけではなく、ブロックを出ると元の値のまま戻ってきます。Python では関数の中のローカル変数が外の変数を隠しましたが、Go ではただの `{}` ブロック（if や for を付けずに `{` と `}` だけで囲んだ範囲。これも 1 つのブロックです）でも同じことが起きます。🟡 「`:=` は新しい変数を作る」ことを意識して、どの変数が見えているか読み取れるようになりましょう。

Python ではこう書いた:

```python
x = 1
def f():
    x = 2  # 関数の中だけの別の x
f()
print(x)  # 1
```

Go ではこう書く:

```go
x := 1
{
	x := 2 // ブロックの中だけの別の x
	fmt.Println(x) // 2
}
fmt.Println(x) // 1
```

### サンプルを1行ずつ読む

| 行 | 外の x | 内の x |
|---|---|---|
| `x := 1` | 1 | （まだない） |
| `x := 100`（if の中） | 1 | 100（新しく作られた別の変数） |
| `x += 5`（if の中） | 1 | 105（内の x だけ増える） |
| if を出た後 | 1 | （消える） |

if の中では同じ名前 `x` が 2 つありますが、見えるのは内側の新しい方だけです。

### 実行結果

```text
外: 1
内: 105
外: 1
```

if の中の `x := 100` を `x = 100`（`:` なし）に変えると、新しい変数は作られず外の `x` への代入になります。その場合の出力は `外: 1` / `内: 105` / `外: 105` です。`:=` と `=` の 1 文字の差で結果が変わります（ch04 でも扱います）。

## ch03 パッケージ変数（global 文はない）

関数の**外**（`func main() { ... }` などの外側、ファイルのいちばん外の段）で宣言した変数を**パッケージ変数**といい、同じパッケージのどの関数からも読み書きできます。Python では関数の中から書き換えるときに `global` 文が必要でしたが、**Go に `global` や `nonlocal` はありません**。関数の外に書けば、宣言なしでそのまま読み書きできます。ただし、どこからでも変えられる変数は追いかけるのが大変なので、基本は引数と戻り値で渡し、パッケージ変数は設定値など最小限にとどめます。🟡

Python ではこう書いた:

```python
count = 0

def add():
    global count  # global 宣言が必要
    count += 1
```

Go ではこう書く:

```go
var count int // 関数の外に書く（パッケージ変数）

func add() {
	count++ // global なしで書き換えられる
}
```

### `var balance = 1000` の書き方

関数の外では `:=` が使えません（`balance := 1000` と書くとコンパイルエラー）。L4 で見た `var` を使います。`var balance = 1000` は型を書かずに初期値から int と決める形、`var count int` は初期値なしでゼロ値 0 から始める形です。

### サンプルを1行ずつ読む

| 行 | balance |
|---|---|
| `var balance = 1000` | 1000 |
| `deposit(500)` → `balance += n` | 1500 |
| `withdraw(200)` → `balance -= n` | 1300 |

`deposit` も `withdraw` も、引数で受け取っていない `balance` を直接書き換えています。どの関数からでも見える変数だからです。

### 実行結果

```text
最初: 1000
最後: 1300
```

## ch04 := が作る意図しない新変数

`:=` は代入ではなく**宣言**です。そのため内側のブロックで外側と同じ名前に `:=` を使うと、意図せず新しい変数を作ってシャドーイングしてしまいます。実務での典型が `if v, err := f(); err == nil {` の形（L10 で見た「条件の前の 1 文」）で、ここで作った `v` や `err` は **if の外では使えません**。Python にはない、`:=` と `=` の使い分けから生まれる実務の落とし穴です。外に残したいときは先に宣言して `=` で代入します。🟡 この違いは Go を書く限りずっとついて回るので、理屈を押さえましょう。

Python ではこう書いた:

```python
n = 0
if True:
    n = int("42")  # 代入はいつも同じ n を指す
print(n)  # 42
```

Go ではこう書く:

```go
n := 0
if true {
	n := 42 // := だと新しい n。外の n は 0 のまま
	_ = n
}
// 外の n に入れたいなら = で代入する
```

### サンプルを1行ずつ読む

- `if v, err := strconv.Atoi("10"); err == nil {` … `"10"` を変換し、成功（`err == nil`、`nil` は「エラーなし」を表す値。L6）なら中に入ります。ここで作った `v` と `err` はこの if の中だけで使えます
- `total += v` … 0+10 = 10
- `var v int` と `var err error` … if の外で使うために、先に宣言しておきます。`error` はエラーを表す型です（L24 で詳しく扱います）
- `v, err = strconv.Atoi("20")` … `:=` ではなく `=` なので、新しい変数は作らず、上で宣言した `v` と `err` に代入します
- `if err == nil { total += v }` … 10+20 = 30

### 実行結果

```text
10
30
```

### 演習で使う `for sc.Scan() { ... }`

L12 で見た `for 条件 {}` の条件に `sc.Scan()` を書いた形です。`Scan()` は 1 行読めたら true、もう行がなければ false を返す（L15 ch01）ので、「入力が続く間ずっと 1 行ずつ読む」ループになります。行数が決まっていない入力を最後まで読むときの定番です。
