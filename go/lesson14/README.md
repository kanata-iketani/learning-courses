# Lesson 14 内包表記の代替

Python入門編「リスト内包表記」に対応するレッスンです。Go にリスト内包表記は存在せず、「空スライス + for + append」の形で書きます。3 行になりますが上から順に読めるのが Go 流で、繰り返し使う変換は関数に切り出します。

## ch01 Go にリスト内包表記は存在しない（for + append で書く）

Go にリスト内包表記は存在しません。**内包表記**（リストを 1 行で生成する Python の構文）で書いていた処理は、Go では「空スライスを作る → for で回す → append（L7 で見た、末尾に要素を足す関数）で追加する」という形で書きます。3 行になるが読める、というのが Go の考え方で、処理の流れが上から順にそのまま追えるため、これが標準の書き方です。🟡 1 行で書けない理由を探すより、この 3 行の型を理屈から理解しましょう。

Python ではこう書いた:

```python
squares = [x * x for x in range(5)]
```

Go ではこう書く:

```go
squares := []int{}
for x := range 5 {
	squares = append(squares, x*x)
}
```

### 3 行の型を1行ずつ読む

- `squares := []int{}` … 要素 0 個の int のスライスを作ります。`{}` の中が空なので中身なし、`len(squares)` は 0 です
- `for x := range 5 {` … L13 で見た形で、`x` が 0, 1, 2, 3, 4 と変わります
- `squares = append(squares, x*x)` … `append` は「元のスライスの末尾に値を足した新しいスライス」を**返す**関数なので、結果を `squares =` で受け取り直します（L7）。受け取り直さないと `squares` は増えません。ここは `:=` ではなく `=` です。`squares` はすでに 1 行目で宣言済みだからです

`squares` は次のように育ちます。

| x | x*x | append 後の squares |
|---|---|---|
| 0 | 0 | [0] |
| 1 | 1 | [0 1] |
| 2 | 4 | [0 1 4] |
| 3 | 9 | [0 1 4 9] |
| 4 | 16 | [0 1 4 9 16] |

### サンプルの後半

- `for _, p := range prices {` … L13 で見た `_` で位置番号を捨て、価格だけを `p` に受けます
- `taxed = append(taxed, p*11/10)` … 1.1 倍（税込み）を整数で計算します。`*` と `/` は左から順に計算されるので、100*11=1100 → 1100/10=110 です。int 同士の `/` は小数点以下を切り捨てます（L3）。80*11/10 は 880/10 = 88 です

### 実行結果

```text
[0 1 4 9 16]
[110 275 88]
```

`fmt.Println` にスライスを渡すと `[要素 要素 …]` の形（カンマなし、空白区切り）で出力されます。演習の期待出力もこの形です。

## ch02 条件付き内包表記の代替（if でフィルタしながら append）

条件付き内包表記（if で要素を絞り込みながらリストを作る Python の書き方）も Go には存在しません。for の中に if を入れ、条件を満たしたときだけ append します。フィルタと変換を同時に行いたい場合も、if の中で加工してから append するだけです。3 行が 4 行になるが読める、という点は前チャプターと同じで、どの行が何をしているか一目で追えます。🟡 「for + if + append」の組み合わせを理屈で理解しましょう。

Python ではこう書いた:

```python
evens = [x for x in nums if x % 2 == 0]
```

Go ではこう書く:

```go
evens := []int{}
for _, x := range nums {
	if x%2 == 0 {
		evens = append(evens, x)
	}
}
```

### サンプルを1行ずつ読む

- `nums := []int{7, 2, 9, 4, 11, 6}` … 元のスライス
- `evens := []int{}` … 結果を入れる空スライス
- `for _, x := range nums {` … 値だけを `x` に取り出します
- `if x%2 == 0 {` … `%` は割った余り（L3）。2 で割って余り 0 なら偶数です。条件が true のときだけ次の行に進みます
- `evens = append(evens, x)` … 偶数のときだけ追加します

1 つ目のループで何が起きるか:

| x | x%2 | 条件 x%2 == 0 | evens |
|---|---|---|---|
| 7 | 1 | false（追加しない） | [] |
| 2 | 0 | true | [2] |
| 9 | 1 | false | [2] |
| 4 | 0 | true | [2 4] |
| 11 | 1 | false | [2 4] |
| 6 | 0 | true | [2 4 6] |

2 つ目のループは条件を `x%2 == 1`（奇数）にし、追加する値を `x*10` に加工しています。7, 9, 11 だけが 70, 90, 110 になって入ります。

### 実行結果

```text
[2 4 6]
[70 90 110]
```

## ch03 関数に切り出すのが Go 流

リスト内包表記がない Go で、for + append のかたまりが何度も登場するなら、関数に切り出すのが Go 流です。Python では内包表記を 1 行で使い回しましたが、Go では「スライスを受け取り、新しいスライスを返す関数」を定義して名前を付けます。関数の定義は L9 の `divmod2` で一度見ました（詳しくは L18 で扱います）。呼び出す側は 1 行になり、内包表記と同じ読みやすさに戻ります。処理に名前が付くぶん、意図はむしろ伝わりやすくなります。🟡 変換処理を関数にまとめる発想を理屈で理解しましょう。

Python ではこう書いた:

```python
doubled = [x * 2 for x in nums]
```

Go ではこう書く:

```go
func double(nums []int) []int {
	result := []int{}
	for _, x := range nums {
		result = append(result, x*2)
	}
	return result
}

// 呼び出す側は 1 行に戻る
doubled := double(nums)
```

### 関数定義 `func squares(nums []int) []int` の読み方

| 部分 | 意味 |
|---|---|
| `func` | 関数を定義するキーワード（Python の `def`） |
| `squares` | 関数名 |
| `(nums []int)` | 引数。名前 `nums`、型は int のスライス。Go では引数名の**後ろ**に型を書きます |
| `[]int`（`)` の後ろ） | 戻り値の型。int のスライスを返す、という宣言です |
| `return result` | 作ったスライスを呼び出し元に返します |

関数は `main` の外（ファイルのいちばん外側）に書きます。

### サンプルを1行ずつ読む

- `squares` … ch01 の 3 行の型（空スライス → for → append）をそのまま関数の中に入れ、最後に `return result` で返します
- `bigOnly` … ch02 の「for + if + append」の型で、`x >= 10` のものだけを集めます（`>=` は「以上」、L11）
- `fmt.Println(squares(nums))` … `nums` は [3 12 5 20]。各要素を 2 乗して [9 144 25 400] が返り、それを出力します
- `fmt.Println(bigOnly(nums))` … 10 以上の 12 と 20 だけが残ります

### 実行結果

```text
[9 144 25 400]
[12 20]
```
