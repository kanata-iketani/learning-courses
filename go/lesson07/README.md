# Lesson 07 スライス

Python入門編「リスト」に対応するレッスンです。Go でリストに当たるのは**スライス**です。`pop` `remove` `del` に当たる関数はなく、末尾削除 `s[:len(s)-1]` や `slices.Delete` のようにスライス操作で書きます。`sorted` の代わりは `slices.Clone` でコピーしてから `slices.Sort` です。

## ch01 スライスの生成と len

Go で Python のリストに当たるのが**スライス**（複数の値を順番に並べて持てるデータ構造）です。`[]int{1, 2, 3}` のように「要素の型」を付けて作り、1 つのスライスには同じ型の値しか入れられない点が Python との大きな違いです。要素数は Python と同じく `len(s)` で数えます。🔴 スライスはこの先すべてのレッスンで使うので、生成の書き方を手が覚えるまで書きましょう。

Python ではこう書いた:

```python
a = [1, 2, 3]
print(len(a))
```

Go ではこう書く:

```go
s := []int{1, 2, 3}
fmt.Println(len(s))
```

### `[]int{10, 20, 30}` を分解する

- `[]`: 「スライス」を表す印（L05 ch03 の `[]rune` と同じ）
- `int`: 中に入れる値（**要素**）の型
- `{10, 20, 30}`: 最初に入れておく要素を、波括弧の中にカンマ区切りで並べる

`[]int` は「int のスライス」、`[]string` は「string のスライス」という型の名前です。`[]int{1, "a"}` のように違う型を混ぜるとコンパイルエラーです。

### サンプルを 1 行ずつ読む

- `nums := []int{10, 20, 30}` → 説明: 3 要素の int のスライス
- `fmt.Println(nums)` → 出力: `[10 20 30]` ／ 説明: Println はスライスを `[ ]` で囲み、要素を空白区切りで表示します（Python のようなカンマは付きません）
- `fmt.Println(len(nums))` → 出力: `3` ／ 説明: 要素数
- `fruits := []string{"りんご", "みかん"}` → 説明: 文字列のスライス
- `fmt.Println(fruits)` → 出力: `[りんご みかん]` ／ 説明: 文字列でも `"` は表示されません
- `var empty []int` → 説明: 要素なしの int のスライス（スライスのゼロ値。`nil` スライスと呼びます）
- `fmt.Println(len(empty))` → 出力: `0`

実行結果:

```text
[10 20 30]
3
[りんご みかん]
0
```

## ch02 s[i] と要素の変更

スライスの要素は Python と同じく `s[i]` で取り出し、`s[i] = 値` で書き換えます。先頭が 0 番なのも同じです。違いは**負のインデックスがない**ことです。Python の `a[-1]` のようには書けず、末尾の要素は `s[len(s)-1]` と書きます。範囲外を指定すると実行時に panic（プログラムの強制終了）になります。🔴 `s[len(s)-1]` は頻出の定型なので、手が覚えるまで書きましょう。

Python ではこう書いた:

```python
a[0] = 99
print(a[-1])
```

Go ではこう書く:

```go
s[0] = 99
fmt.Println(s[len(s)-1])
```

### インデックスの数え方

`colors := []string{"赤", "青", "黄"}` のとき:

```text
インデックス:  0    1    2
要素:         赤   青   黄
```

要素が 3 個なので `len(colors)` は 3、最後のインデックスは `3 - 1 = 2` です。だから `colors[len(colors)-1]` は `colors[2]`、つまり末尾の「黄」になります。

### サンプルを 1 行ずつ読む

- `fmt.Println(colors[0])` → 出力: `赤` ／ その後の colors: `[赤 青 黄]`
- `colors[1] = "緑"` → その後の colors: `[赤 緑 黄]`（1 番目を書き換え）
- `fmt.Println(colors)` → 出力: `[赤 緑 黄]`
- `fmt.Println(colors[len(colors)-1])` → 出力: `黄`

実行結果:

```text
赤
[赤 緑 黄]
黄
```

### 範囲外を指定したとき

要素が 3 個のスライスで `s[5]` を読もうとすると、コンパイルは通りますが、実行したその行でプログラムが止まり、次のように表示されます。

```text
panic: runtime error: index out of range [5] with length 3
```

「長さ 3 なのにインデックス 5 を指定した」という意味です。`s[-1]` はコンパイルエラーになります。

## ch03 スライス式 s[i:j]

スライスの一部を切り出す**スライス式** `s[i:j]` は、Python の `a[1:3]` とほぼ同じで、i 番目から j-1 番目までを取り出します。始点や終点の省略（`s[:2]` `s[2:]`）も同じです。違いは 2 つあり、負のインデックスが使えないこと（`a[:-1]` は `s[:len(s)-1]` と書く）と、ステップ指定 `a[::2]` が存在しないことです。🔴 切り出しはコーディングテスト頻出なので、手が覚えるまで書きましょう。

Python ではこう書いた:

```python
print(a[1:4])
print(a[:-1])
```

Go ではこう書く:

```go
fmt.Println(s[1:4])
fmt.Println(s[:len(s)-1])
```

### `[i:j]` の範囲を表で見る

`nums := []int{1, 2, 3, 4, 5}` のとき:

```text
インデックス:  0  1  2  3  4
要素:          1  2  3  4  5
```

- `nums[1:4]` → 取り出す範囲: 1 番目から 3 番目（4 は含まない） ／ 結果: `[2 3 4]`
- `nums[:2]` → 取り出す範囲: 先頭から 1 番目（始点を省略すると 0） ／ 結果: `[1 2]`
- `nums[3:]` → 取り出す範囲: 3 番目から最後まで（終点を省略すると len） ／ 結果: `[4 5]`
- `nums[:len(nums)-1]` → 取り出す範囲: `nums[:4]` と同じ。末尾 1 つを除く ／ 結果: `[1 2 3 4]`

取り出される個数は `j - i` 個です（`[1:4]` なら 3 個）。

実行結果:

```text
[2 3 4]
[1 2]
[4 5]
[1 2 3 4]
```

### 切り出した結果は元と中身を共有する

`t := nums[1:4]` で作った t は、nums の要素の一部を指しているだけで、要素はコピーされません。そのため `t[0] = 99` とすると `nums[1]` も 99 になります。Python のスライスはコピーを作るので、ここは違います。詳しい理由は L25 で学びます。

## ch04 append で追加

要素の追加は `append` で行います。Python の `a.append(x)` はリストをその場で変更しましたが、Go の `append` は**追加後のスライスを返す関数**なので、`s = append(s, x)` と必ず戻り値を再代入します。この再代入を忘れると追加が反映されません。`append(s, 1, 2)` のように一度に複数追加もできます。🔴 `s = append(s, x)` の形を手が覚えるまで書きましょう。

Python ではこう書いた:

```python
a.append(4)
```

Go ではこう書く:

```go
s = append(s, 4)
```

### `s = append(s, x)` を分解する

1. `append(s, x)` が「s の末尾に x を足したスライス」を作って戻り値として返します
2. `s =` でその戻り値を s に入れ直します（L04 ch03 の再代入）

Python は `a.append(4)` のように「リストに付いた機能（メソッド）」を呼びましたが、Go の append は `len` と同じく、最初から使える関数（**組み込み関数**、import 不要）です。

### サンプルで s がどう変わるか

- `var nums []int`: `[]`（空、L07 ch01）
- `nums = append(nums, 10)`: `[10]`
- `nums = append(nums, 20)`: `[10 20]`
- `nums = append(nums, 30, 40)`: `[10 20 30 40]`

実行結果:

```text
[10 20]
[10 20 30 40]
4
```

`append(nums, 10)` だけを書いて戻り値を受け取らないと、`append(nums, 10) (value of type []int) is not used`（戻り値が使われていない）というコンパイルエラーになります。

## ch05 append で結合（s2...）

スライス同士の結合も `append` で行います。第 2 引数にスライス名と `...` を付けると、要素を展開して 1 つずつ追加した扱いになります。Python の `a + b` や `a.extend(b)` に当たる書き方です。`...` を忘れると「型が違う」というコンパイルエラーになります。🟡 なぜ `...` が必要なのか（append はスライスではなく要素を受け取る関数だから）を理屈で理解しましょう。

Python ではこう書いた:

```python
c = a + b
```

Go ではこう書く:

```go
c := append(a, b...)
```

### `b...` の意味

`a := []int{1, 2}`、`b := []int{3, 4}` のとき、次の 2 行は同じ結果になります。

```go
c := append(a, b...)
c := append(a, 3, 4) // b... はこう書いたのと同じ
```

`...`（ドット 3 つ）は、スライスの後ろに付けると「中身をばらして 1 つずつ並べた形で渡す」という意味になります。Python の `*b` に近い記号です。

### `...` を忘れたときのエラーの実物

`append(a, b)` と書くと、int のスライスに「[]int という 1 つの値」を足そうとしたことになり、次のエラーが出ます。

```text
cannot use b (variable of type []int) as int value in argument to append
```

「[]int 型の b を、append の引数の int として使えない」という意味です。

### サンプルの実行結果

- `c := append(a, b...)`: `[1 2 3 4]`
- `len(c)`: `4`
- `x = append(x, []string{"夜"}...)`: `[]string{"夜"}` はその場で作った 1 要素のスライス。展開して足すので `[朝 昼 夜]`

```text
[1 2 3 4]
4
[朝 昼 夜]
```

## ch06 要素の削除（pop・remove・del はない）

Go には Python の `pop` `remove` `del` に当たる関数が**ありません**。削除はスライス操作で書きます。末尾の削除は `s = s[:len(s)-1]`、i 番目の削除は標準パッケージ `slices` の `slices.Delete(s, i, i+1)` を使い、どちらも結果を再代入します。Delete の 2 つの引数は「i 番目から j-1 番目までを消す」という範囲指定です。🟡 「削除は専用関数ではなくスライス操作で書く」という考え方を理解しましょう。

Python ではこう書いた:

```python
a.pop()
del a[1]
```

Go ではこう書く:

```go
s = s[:len(s)-1]
s = slices.Delete(s, 1, 2)
```

### 使うための準備

`slices` はスライス操作の関数を集めた標準パッケージ（Go 1.21 で追加）です。`import ( )` に `"slices"` を足して使います。

### サンプルで s がどう変わるか

- `s := []string{"a", "b", "c", "d"}` → 実行後の s: `[a b c d]`
- `s = s[:len(s)-1]` → 実行後の s: `[a b c]` ／ 説明: `s[:3]`（0〜2 番目）を切り出して s に入れ直す＝末尾を削除（L07 ch03）
- `s = slices.Delete(s, 1, 2)` → 実行後の s: `[a c]` ／ 説明: 1 番目から 1 番目まで（2 は含まない）＝ `"b"` だけを消す

`slices.Delete(s, i, j)` の i と j は ch03 のスライス式 `s[i:j]` と同じ数え方で、「`s[i:j]` の部分を消す」と読めます。`slices.Delete(s, 1, 3)` なら 1 番目と 2 番目の 2 つを消します。

実行結果:

```text
[a b c]
[a c]
```

## ch07 slices.Sort で並べ替え

並べ替えは標準パッケージ `slices` の `slices.Sort(s)` で行います。Python の `a.sort()` と同じく**その場で**昇順に並べ替え、戻り値はありません。int でも string でも同じ書き方で使えます。以前は `sort.Ints(s)` のように型ごとの関数を使っていたため、古いコードではそちらも見かけます。🔴 ソートはコーディングテスト頻出なので、`slices.Sort` を手が覚えるまで書きましょう。

Python ではこう書いた:

```python
a.sort()
```

Go ではこう書く:

```go
slices.Sort(s)
```

### 用語の確認

- **昇順**: 小さい順（1, 2, 3 …）。逆の大きい順は**降順**です
- **その場で並べ替える**: 新しいスライスを作らず、渡したスライスの中身そのものを並べ替えること。だから `s = slices.Sort(s)` とは書かず、`slices.Sort(s)` だけを書きます（戻り値がないので、代入しようとするとエラーです）
- 文字列の昇順は辞書順（文字の番号の小さい順）です。英字なら a → z の順になります

### サンプルの実行結果

- `slices.Sort(nums)`: nums が `[3 1 4 1 5]` から `[1 1 3 4 5]` に
- `slices.Sort(names)`: names が `[banana apple cherry]` から `[apple banana cherry]` に

```text
[1 1 3 4 5]
[apple banana cherry]
```

`sort.Ints(s)` を使うときは `import "sort"` が必要で、動きは `slices.Sort(s)` と同じです。

## ch08 コピーしてからソート（sorted の代替）

Python の `sorted(a)` は元のリストを変えずに、並べ替えた新しいリストを返しましたが、Go に相当する関数はありません。代わりに `slices.Clone(s)`（スライスの複製を作る関数）でコピーしてから、コピーの方を `slices.Sort` します。コピーせずに Sort すると元の並びが失われるため、「元も残したいならまず Clone」が定型です。🟡 なぜコピーが必要なのか（Sort はその場で書き換えるから）を理解しましょう。

Python ではこう書いた:

```python
b = sorted(a)
```

Go ではこう書く:

```go
b := slices.Clone(a)
slices.Sort(b)
```

### `b := a` ではコピーにならない

スライスを `b := a` と代入しても、要素はコピーされず、b と a は同じ中身を指します（ch03 の「中身を共有する」と同じ理由）。そのため `slices.Sort(b)` をすると a も並べ替わってしまいます。`slices.Clone(a)` は要素を 1 つずつ写した別のスライスを作るので、b を変えても a は変わりません。

### サンプルで 2 つのスライスがどう変わるか

- `scores := []int{30, 10, 20}` → scores: `[30 10 20]` ／ ranked: （まだない）
- `ranked := slices.Clone(scores)` → scores: `[30 10 20]` ／ ranked: `[30 10 20]`（別の複製）
- `slices.Sort(ranked)` → scores: `[30 10 20]` ／ ranked: `[10 20 30]`

実行結果:

```text
[10 20 30]
[30 10 20]
```
