# Lesson 25 値とポインタ

Python入門編「イミュータブルとミュータブル」に対応するレッスンです。Python の `id()` に相当するものは Go になく、「配列や構造体は値としてコピー、スライスとマップは中身を共有」という区別で考えます。最後に `&` と `*` のポインタで、関数から呼び出し元の変数を変える方法を学びます。

## ch01 値型のコピー（int・struct・配列は代入で複製）

Python ではすべての変数がオブジェクトへの参照で、`id()` で同一性を確かめられましたが、Go に `id()` はありません。代わりに「型ごとのコピーのされ方」で考えます。`int`・構造体・配列（固定長。L9 ch03 で見た `[3]int` の形）は**値型**（代入や引数渡しで中身が丸ごと複製される型）です。コピーを書き換えても元の変数は変わりません。配列が値としてコピーされる点は、Python のリストとの大きな違いです。🟡 「代入=複製」になる型を押さえましょう。

Python ではこう書いた:

```python
a = [1, 2, 3]
b = a       # 同じオブジェクトを指す
b[0] = 100  # a も変わる
```

Go ではこう書く:

```go
a := [3]int{1, 2, 3} // 配列は値型
b := a               // 中身が丸ごとコピーされる
b[0] = 100           // a は変わらない
```

### サンプルを1行ずつ読む

| 行 | p（または a・x） | q（または b・y） |
|---|---|---|
| `p := Point{X: 1, Y: 2}` → `q := p` | {1 2} | {1 2}（別の箱にコピー） |
| `q.X = 100` | {1 2} | {100 2} |
| `a := [3]int{1, 2, 3}` → `b := a` | [1 2 3] | [1 2 3]（別の箱にコピー） |
| `b[0] = 100` | [1 2 3] | [100 2 3] |
| `x := 10` → `y := x` → `y = 999` | 10 | 999 |

`type Point struct { X, Y int }` の `X, Y int` は、同じ型の項目を 1 行にまとめた書き方です（L21 ch02）。`[3]int{1, 2, 3}` は長さ 3 の配列で、`[]int{1, 2, 3}`（`[]` の中が空）はスライスです。見た目は 1 文字違いですが、コピーのされ方が違います（ch02）。

### 実行結果

```text
1 100
1 100
10 999
```

L20 ch01 の「引数は値渡し」も同じ仕組みです。関数に構造体や配列を渡すと、中身が丸ごとコピーされます。

## ch02 スライスとマップが「参照的」に振る舞う理由

スライスの実体は「配列へのポインタ（L20 で見た、場所を指す値）・長さ（今入っている要素数、`len`）・容量（確保済みの置き場所の数、`cap`）」の 3 つだけを持つ小さな**ヘッダ**（管理用の情報）です。代入でコピーされるのはこのヘッダだけで、中身の配列は共有されたままです。そのため片方の要素を変えると、もう片方からも変わって見えます。マップも同様に内部データへの参照を持ちます。Python のリストや辞書の共有と同じ見た目ですが、Go では「同じ配列を指しているから」と理由まで説明できます。🟡 ヘッダと配列の関係を理解しましょう。

Python ではこう書いた:

```python
a = [1, 2, 3]
b = a       # 同じリストを指す
b[0] = 100  # a も [100, 2, 3]
```

Go ではこう書く:

```go
a := []int{1, 2, 3}
b := a     // ヘッダのコピー。中身の配列は同じ
b[0] = 100 // a も [100 2 3] になる
```

### ヘッダと配列の関係

`a := []int{1, 2, 3}` と `b := a` の後は、次の状態です。

| | 配列の場所 | 長さ | 容量 |
|---|---|---|---|
| a のヘッダ | 配列 X | 3 | 3 |
| b のヘッダ | 配列 X（同じ） | 3 | 3 |

配列 X の中身は `[1 2 3]` が 1 つだけです。`b[0] = 100` は配列 X の 0 番目を書き換えるので、同じ X を指す `a` から見ても `[100 2 3]` です。ch01 の配列 `[3]int` との違いは、代入でコピーされるのが「中身」か「ヘッダだけ」かです。

### サンプルを1行ずつ読む

- `a := []int{1, 2, 3}` → `b := a` → `b[0] = 100` … 上の表のとおり、`a` も `b` も `[100 2 3]`
- `m1 := map[string]int{"apple": 150}` → `m2 := m1` → `m2["apple"] = 200` … map も代入で中身は複製されないので、`m1["apple"]` も 200

### 実行結果

```text
[100 2 3]
[100 2 3]
200
```

### 中身を別にしたいとき

中身ごと別のスライスにしたいときは、L7 ch08 で見た `b := slices.Clone(a)` を使います。こうすると `b[0]` を変えても `a` は変わりません。

### append には注意

`b = append(b, 4)` で容量（ここでは 3）を超えると、Go は新しい配列を用意して中身を移し、`b` だけがそちらを指すようになります。その後の `b[0] = 100` は `a` に届きません。

```go
a := []int{1, 2, 3}
b := a
b = append(b, 4) // 容量 3 を超えたので b は新しい配列へ
b[0] = 100
fmt.Println(a, b) // [1 2 3] [100 2 3 4]
```

「共有されているかどうか」が append で変わることがあるので、別々に扱いたいスライスは最初から `slices.Clone` でコピーしておくのが安全です。

## ch03 ポインタ（& と * で呼び出し元を変える）

**ポインタ**は変数のメモリ上の場所を指す値です。`&x` で x のポインタを取り、`*p` で指し先の値を読み書きします（デリファレンスと呼びます）。L20 ch02 で見た記号のおさらいです。Go の引数は常に値渡しでコピーされるため、関数の中から呼び出し元の変数を書き換えたいときはポインタを渡します。Python では引数への再代入は呼び出し元に届きませんでしたが、Go はポインタで「届かせる」ことを明示できます。🟡 & と * の役割を理解しましょう。

Python ではこう書いた:

```python
def add_ten(n):
    n += 10  # 呼び出し元の変数は変わらない
```

Go ではこう書く:

```go
func addTen(p *int) {
	*p += 10 // 指し先を書き換える → 呼び出し元が変わる
}

addTen(&x)
```

### サンプルを1行ずつ読む

| 行 | x | 説明 |
|---|---|---|
| `x := 5` | 5 | |
| `addTenValue(x)` | 5 | `n` は x のコピー。コピーが 15 になるだけ |
| `addTen(&x)` | 15 | `p` は x の場所。`*p += 10` は x そのものに 10 を足す |
| `p := &x` | 15 | `p` は x の場所（型は `*int`） |
| `fmt.Println(*p)` | 15 | `*p` で場所の中身を読む |

`fmt.Println(p)` と `*` を付けずに出すと、`0xc000012345` のような場所の番号（アドレス）が出ます。番号は実行のたびに変わります。

### 実行結果

```text
5
15
15
```

### nil ポインタに注意

`var q *int` と宣言しただけのポインタは、どこも指していない nil です。`*q` で中身を読もうとすると、実行中に次のように止まります。

```text
panic: runtime error: invalid memory address or nil pointer dereference
```

「無効なメモリの場所を読もうとした」という意味で、Go で最もよく見る実行時エラーの 1 つです。ポインタは `&x` のように実際の変数から作ってから使います。
